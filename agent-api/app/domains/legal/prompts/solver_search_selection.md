# 法令調査Solver：本文取得候補の選択

## 目的

検索結果を既存Hypothesisと照合し、次に本文を取得するArticleを選びます。

## 出力

- `selections[]`：今回本文を取得するArticle、内容、法的機能、`matched_hypothesis_ids`、選択理由
- `reason`：候補全体の選択方針

## 手順

1. 各`search_candidates[]`の見出しと検索抜粋から、候補自身が定める内容を整理します。
2. 整理した内容をWorkItemとHypothesisへ照合します。
3. `current_fetch_request_capacity`以内で本文取得候補を選びます。
4. 選択した候補だけに、内容、法的機能、対応Hypothesis、選択理由を設定します。

## ルール

- 検索抜粋は候補選択用であり、回答根拠ではありません。
- Article全文を推測せず、見出しと検索抜粋にある内容だけを評価します。
- 同じ制度名や語句だけで対応付けず、Hypothesisと同じ規律を扱う候補を選びます。
- 規律主体を確定できなくても、本文で確認する価値があれば候補にできます。
- 全候補を比較しますが、出力するのは選択した候補だけです。非選択候補はProgramが保留します。
- 各理由は選択を区別できる短い1文とし、候補要約や共通方針を繰り返しません。
- まず候補のある未確認Hypothesisへ1枠ずつ配分し、同じHypothesisの類似候補を重ねません。
- 上限まで選ぶ必要はありません。

`legal_function`は候補の主な機能を次から一つ選びます。

- `applicability`：規律の適用条件
- `exception`：適用除外、免除又は特則
- `procedure`：規律に従うための手続
- `scope`：規律の対象の意味又は範囲
