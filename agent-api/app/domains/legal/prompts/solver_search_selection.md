# 法令調査Solver：本文取得候補の選択

## 目的

検索結果を既存Hypothesisと照合し、次に本文を取得するArticleを選びます。

## 出力

- `selections[]`：今回本文を取得するArticle、内容、法的機能、`matched_hypothesis_ids`、選択理由
- `reason`：候補全体の選択方針

## 手順

1. 各`search_candidates[]`の見出しと検索抜粋から、候補自身が定める内容を整理します。
2. 整理した内容をWorkItemとHypothesisへ照合します。
3. `non_work_item_requirements[]`のうち、根拠の提示等、本文取得に関係する要件も確認します。
4. `current_fetch_request_capacity`以内で本文取得候補を選びます。
5. 選択した候補だけに、内容、法的機能、対応Hypothesis、選択理由を設定します。

## ルール

- 検索抜粋は候補選択用であり、回答根拠ではありません。
- Article全文を推測せず、見出しと検索抜粋にある内容だけを評価します。
- 同じ制度名や語句だけで対応付けず、Hypothesisと同じ規律を扱う候補を選びます。
- 規律主体を確定できなくても、本文で確認する価値があれば候補にできます。
- 全候補を比較しますが、出力するのは選択した候補だけです。非選択候補はProgramが保留します。
- 同じArticleが複数のHypothesisに対応する場合も、Articleは1件だけ出力し、対応するIDを
  `matched_hypothesis_ids`へまとめます。
- 各理由は選択を区別できる短い1文とし、候補要約や共通方針を繰り返しません。
- まず候補のある未確認Hypothesisへ1枠ずつ配分します。残りの枠は、質問が明示した条件、範囲又は実施方法を
  直接定める候補へ配分し、付随書類や質問にない運用詳細を後にします。
- 同じHypothesisに複数候補がある場合は、`gaps`にある未確認事項を直接定める候補を先にします。
  広い規律や追加条件を扱う候補によって、質問が明示した基準、値又は範囲を直接定める候補を後回しにしません。
- 同じHypothesisでも、上位規定とその具体化規定等、異なる規定内容を確認するために必要なら複数Articleを
  選べます。同じ内容の候補は重ねません。
- `gaps`があるHypothesisは、その未確認内容を候補と照合します。
- 法的根拠の提示が求められ、規律を置く規定と具体化する規定の両方が候補にある場合は、
  取得枠内で両方を選べます。文体や長さ等の回答形式だけを理由に候補を追加しません。
- 質問が明示した起点規定と他の規定との関係又は改正影響を確認する場合は、起点規定も比較に必要な候補として
  扱います。
- 上限まで選ぶ必要はありません。

`legal_function`は候補の主な機能を次から一つ選びます。

- `applicability`：規律の適用条件
- `exception`：適用除外、免除又は特則
- `procedure`：規律に従うための手続
- `scope`：規律の対象の意味又は範囲
