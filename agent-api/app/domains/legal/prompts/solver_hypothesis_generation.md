# 法令調査Solver：法的仮説の立案

## 目的

WorkItemに答えるため、法令本文で個別に検証する暫定的な法的命題を作ります。

## 完了条件

- すべてのWorkItemを扱っている。
- 各`statement`が、暫定的な法的効果を示す1つの文である。
- WorkItemから分からない分類、要件又は手続を予想して追加していない。
- 各`gaps`が、WorkItemで問われた未確認内容に直接対応している。
- 出力がschemaに従っている。

## 手順

1. WorkItemと任意の`answer_options[]`を確認します。回答候補の内容は確認済み事実として扱いません。
2. WorkItemに示された事実と、暫定的な法的効果を結び付けた命題を考えます。
3. WorkItem自体に独立した確認事項が複数ある場合だけ、命題ごとにHypothesisを分けて`statement`へ書きます。
4. `statement`とは別に、結論の判定に必要な未確認事項があれば`gaps`へ書きます。なければ空にします。

## ルール

- 1つの`statement`には、独立して適用され得る条件、義務又は回答事項を1つだけ書きます。
- 複数の回答事項を「、」「及び」「又は」等で列挙せず、それぞれ別のHypothesisにします。
- 命題の理解に必要な主体、行為、対象、条件及び効果は、同じ`statement`に含めて構いません。
- Hypothesisは本文で支持又は否定される未確認の命題です。
- WorkItemに示された事実を保ち、質問にない判定軸や基準を`statement`へ補いません。法令上の要件や基準は`gaps`に残します。
- WorkItemにない行為者、数値又は条文番号を確定しません。
- WorkItemが未知の種類、範囲又は一覧を問う場合、その構成要素を予想してHypothesisへ追加しません。求める範囲又は一覧を1つの命題として扱い、具体的内容は`gaps`に残します。
- 回答に含まれそうな事項を予想しただけでは、Hypothesisを分けません。
- WorkItemが扱わない前提、例外、周辺手続又は事後対応へ範囲を広げません。
- `gaps`には、WorkItemのどの表現に対応するか説明できる未確認内容だけを書きます。
- 各Hypothesisの初期`gaps`は、WorkItemで問われた未確認内容をまとめた1件だけにします。予想した内訳へ分けません。
- `gaps`へ予想した候補や例を列挙せず、括弧書きでも補いません。
- 根拠法令の特定又は適用前提は、WorkItemがそれを問う場合だけ`gaps`にします。
- 検索方針は書きません。

### 条件を問うWorkItem

- `statement`には、WorkItemに示された行為が規律の対象になるかという暫定的な法的効果を書きます。
- その法的効果を左右する法令上の要件が不明なら、推測せず`gaps`に書きます。
