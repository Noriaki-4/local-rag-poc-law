# 法令調査Solver：法的仮説の立案

## 目的

提示されたWorkItemについて、法令本文で検証する仮説を作ります。これは本文取得前の検索計画です。適用除外又は例外を問われた場合は、未知の答えを予想せず、探すべき規定の構造を仮説にします。

## 完了条件

- 提示されたWorkItemにHypothesisが1件以上ある。
- 適用除外又は例外では、`statement`から探すべき原則規定、例外規定又は委任規定の役割が分かる。
- それ以外では、`statement`が法令本文によって支持又は否定できる暫定的な結論になっている。
- WorkItemにない法的論点が追加されていない。

## 手順

1. WorkItemを確認します。
2. 現在のWorkItem自身が適用除外又は例外を問う場合だけ、例外用のルールを使います。
3. それ以外のWorkItemでは、法的論点に対する暫定的な結論を`statement`に書きます。
4. 例外以外の複数の種類を問うWorkItemでは、具体的な候補ごとにHypothesisを分けます。

## ルール

### 適用除外・例外

- このルールは、現在の`work_items[].question`自身が適用除外又は例外を問う場合だけ使います。成立条件、対象範囲又は手続を問うWorkItemには使いません。
- 例外規定は、原則規定の適用を排除、限定又は修正する規定です。
- 検索前に未知の除外事由、数値又は対象者を推測しません。
- `statement`は次の文型のいずれかにし、角括弧の部分だけをWorkItemの表現で置き換えます。
  - 「[義務又は規制]を定める原則規定に対し、別の例外規定が適用を排除又は限定する要件を定めている。」
  - 「[適用除外となる条件]の具体化は下位法令へ委任され、委任先が具体的要件を定めている。」
- 文型にない条件や具体例を付け足しません。
- 本文未取得時は委任の有無も未確認です。WorkItemだけから一方が不要と分からない限り、2つの検索経路を別々のHypothesisとして出力します。
- 「適用除外がある」「義務が免除される」だけの結論は書きません。

### それ以外

- WorkItemと一般的な法的知識から、誤り得る暫定的な結論を書きます。
- 法令本文によって支持又は否定できる1つの命題にします。
- 仮説なので誤りは許容されます。確認済みの事実として扱いません。
- 「特定の条件」「特定の場合」「特定のもの」「法令で定める」のような、内容のない表現でWorkItemを言い換えません。
- 複数の種類を問われた場合は、具体的な候補を複数返します。

### 共通

- 根拠法令名、条文番号、検索語、検索作業は書きません。
