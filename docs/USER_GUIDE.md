# 利用者ガイド（法令RAG 質問デモ）

このガイドは、法令RAG POCに**人間が自然言語で質問する**方法と、**デジタル庁データセット
（lawqa_jp）の問題を手動でテストする**方法をまとめたものです。
セットアップ・運用の詳細は [RUNBOOK.md](../RUNBOOK.md) を参照してください。

---

## 1. できること

- 投入済みの法令・ガイドラインに基づいて、日本語の質問に回答します。
- 回答には**根拠とした条文・資料を引用**します（条文本文・出典つき）。
- 複数法令を引用した場合は、親法・施行令・施行規則等の関係と、その回答で併せて参照した
  法令を**根拠関係図**で確認できます。
- 選択式（4択）でも質問でき、その場合はどの選択肢が正解かも判定します。

回答は検索された条文に基づく参考情報です。**法的判断そのものを断定するものではなく、
重要な判断は専門家に確認してください。**

---

## 2. 回答できる範囲

質問は**投入済みの法令・ガイドラインの範囲**に限られます。範囲外を聞くと
「引用できる条文が見つかりませんでした」と表示されるか、確度の低い回答になります。

| 分野 | 投入されている法令・資料 | 注意 |
|---|---|---|
| 借地借家・賃貸借 | 借地借家法、民法（賃貸借） | **民法は賃貸借（第601〜622条の2）のみ**。総則・物権・相続などは対象外 |
| 金融商品取引法 | 金商法本体・施行令・関連府省令、監督指針/開示/公開買付けの各ガイドライン | 全条投入 |
| 薬機法 | 医薬品医療機器等法・施行規則、法令遵守ガイドラインQ&A・適正広告基準 | 全条投入。対応表の条文はグラフ（EXPLAINS）で紐付け済み |

外部ガイドライン（PDF、6件）: 金融庁の監督指針・開示ガイドライン・公開買付けQ&A、
厚労省の法令遵守ガイドラインQ&A・適正広告基準、国交省の原状回復ガイドライン。

> 実際に投入されるのは `SEED_LAWQA_EGOV=true`（法令）と `SEED_EXTERNAL_GUIDANCE=true`
> （ガイドライン）を指定して seed した場合です。詳細は RUNBOOK.md の該当節を参照。

## 3. UIで質問する

### 3.1 起動

```bash
docker compose up --build -d
```

ブラウザで **http://localhost:8501** を開きます（`agent-ui` サービス）。
API 単体の疎通確認は `curl -s http://localhost:8000/health | jq .`。

### 3.2 使い方

1. メイン画面上部の**法令横断の質問例（Lv.1〜Lv.4）**には、12件の質問全文と想定する
   参照先、採点基準の法令時点が難易度別に一覧表示されます。例はすべて複数の資料を
   横断する内容です。
2. 試したい質問文を一覧からコピーし、入力欄へ貼り付けます。
3. 必要に応じて質問を編集し、**「質問する」**を押します（回答生成に最大10分程度）。
4. **引用した資料の内訳**で、引用された法令・資料の種類数と一覧を確認します。例題を
   そのまま入力した場合は、**想定参照先へ到達できたかの答え合わせ表**も表示されます。
5. **引用した条文・資料**を開くと、条文本文と出典が読めます。

根拠関係図の線種は3種類です。**実線**はグラフ上で確認できた条文参照・解説関係、**点線**は
法令名の命名規則からの推定（条文同士の委任関係までは未確認）、**破線**は正式な上下関係では
なくその回答で併せて参照した関係です。

「詳細設定（開発者向け）」は通常触る必要はありません。探索方式（pattern）の変更、
選択式（4択）入力、引用件数などの調整、検索ルート/グラフ/traceの表示に使います。

### 3.3 質問のコツ

- **自然な日本語**で構いません。「〜は何年ですか」「〜に〜は含まれますか」
  「〜の場合に必要な措置は何ですか」のように具体的に。
- **「根拠条文も示してください」**と付けると、引用条文が明確になります。
- **法令名は書かなくて構いません。** どの法令・ガイドラインを見るべきかを探すのが
  このシステムの役割です。質問例も法令名を書かない形にしてあります。
- うまく引けないときの手段として、対象の**分野の語**（借地、有価証券報告書、
  製造販売業 など）を足すと絞り込まれます。法令名まで書くと検索対象を人が指定したことに
  なるため、**まずは書かずに試す**のが本来の使い方です。

### 3.4 法令横断の質問例と難易度

難易度は論点の多さではなく、**横断する資料の構造**（何階層の法令まで、ガイドラインまで
参照する必要があるか）で分類しています。

| 難易度 | 分類 | 横断の構造 |
|---|---|---|
| Lv.1 | 一般法と特別法の読み分け | 2つの法律のどちらが適用されるか、どう補い合うかを読み分ける |
| Lv.2 | 法律と下位法令の突き合わせ | 法律が定める要件と、施行規則・内閣府令の具体的な手続を突き合わせる |
| Lv.3 | 法律・政令・府令の3階層 | 委任の連鎖を法律から政令・府令までたどり、要件・例外・手続を組み立てる |
| Lv.4 | 法令と行政ガイドラインの突き合わせ | 条文だけでは判断基準が読み取れず、監督指針・Q&A・基準のPDFまで参照する |

Lv.1・Lv.2・Lv.4は各3件、Lv.3は9件、計18件を用意しています。**質問文には原則として参照先の
法令名を書いていません。**法令名を書くと検索対象を人が指定したことになり、必要な資料を自力で
見つけられるかを試せなくなるためです。ただし、既知の改正元から影響先を探す設問では、その改正元を
検索起点として質問に含めます。下表の「主な参照先」は答え合わせ用で、質問文には含まれません。

> **例題は投入済みの条文が実在することを確認したうえで作っています。** デモとして
> 成立させるためですが、その分**実運用の質問より条件が良い**ことに注意してください。
> 例題が通ることは、任意の法務質問に答えられることを意味しません。システムの実力は
> 例題ではなく、第5章のデジタル庁データセット（自作でない140問）で確認してください。

| 難易度 | 確認する内容 | 主な参照先（答え合わせ用） |
|---|---|---|
| Lv.1 | 建物所有目的の土地賃貸借と、それ以外の土地賃貸借の期間ルール | 民法、借地借家法 |
| Lv.1 | 賃貸住宅終了時の明渡し条件、原状回復、敷金返還 | 借地借家法、民法 |
| Lv.1 | 借地上の建物を売却する際の借地権譲渡と地主の承諾 | 民法、借地借家法 |
| Lv.2 | 医薬品製造販売業者の法令遵守体制と具体的業務 | 薬機法、同施行規則 |
| Lv.2 | 医薬品の製造販売業の許可区分・許可基準・申請書類 | 薬機法、同施行規則 |
| Lv.2 | 有価証券報告書の提出対象・期限・記載添付事項 | 金融商品取引法、開示府令 |
| Lv.3 | 少人数私募で有価証券届出書が不要となる条件・人数の数え方・転売制限 | 金融商品取引法、同施行令、定義府令 |
| Lv.3 | 市場外で株券を買い集める場合の公開買付規制 | 金融商品取引法、同施行令、公開買付府令 |
| Lv.3 | 役職員への譲渡制限付株式交付時の届出・対象者・譲渡制限期間 | 金融商品取引法、同施行令、開示府令 |
| Lv.3 | 少数所有者の場合の公開買付けの適用除外と具体的条件 | 金融商品取引法、同施行令、公開買付府令 |
| Lv.3 | 少数所有者の適用除外で使う「特別関係者」の定義元 | 金融商品取引法、同施行令、公開買付府令 |
| Lv.3 | 公開買付開始公告で選択できる方法、共通掲載事項、方法別条件 | 金融商品取引法、同施行令、公開買付府令 |
| Lv.3 | 電子公告を原則とする社内方針の適法性と修正点 | 金融商品取引法、同施行令、公開買付府令 |
| Lv.3 | 公開買付開始公告の上位規定改正による下位法令への影響 | 金融商品取引法、同施行令、公開買付府令 |
| Lv.3 | 非居住公開買付者の公告・届出・国内代理人に関する社内手順 | 金融商品取引法、同施行令、公開買付府令 |
| Lv.4 | 退去時の通常損耗・経年変化を借主負担にできるかの判断 | 民法、原状回復ガイドライン（国交省） |
| Lv.4 | 医薬品の広告で禁止される表現、承認前医薬品の広告可否 | 薬機法、医薬品等適正広告基準（厚労省） |
| Lv.4 | 高齢顧客へのリスク商品勧誘に求められる社内体制 | 金融商品取引法、総合的な監督指針（金融庁） |

例題の採点基準はUIに表示する「法令時点」の現行法を前提とする。公開買付け例題は、
2026年5月1日施行の改正後規定に合わせ、従来の3分の1基準ではなく30%基準を確認する。

質問全文と「想定する参照先」はUIのメイン画面に一覧表示されます。例題をそのまま入力すると、
回答後に次の3段階の結果が表で示されます。

1. **想定資料**: 必要な法律・政令・府令・ガイドラインを引用したか
2. **必要条文・資料**: 質問に答えるための条文を引用したか
3. **回答要点**: 質問された論点を回答本文で説明したか

例えば、退去時の質問で民法619条だけを引用しても、「民法へ到達」は満たしますが、
原状回復の621条と敷金の622条の2を引用していないため、必要条文の判定は未確認になります。
条文IDは区切りまで一致させるため、第3条を期待しているときに第30条を誤って一致扱いしません。

採点基準は [example_questions.py](../agent-ui/example_questions.py) に置かれ、**APIから回答を
受け取った後にだけ使用します**。質問、検索クエリ、再ランキング、回答生成プロンプトには
必須条文や回答要点を渡しません。例題の正解情報で検索を有利にしないためです。

回答要点は表記揺れを許す決定的な文字列照合で確認します。これは明白な欠落を検出するための
回帰チェックであり、法的正確性や論理的な当てはめを自動保証するものではありません。
最終的な内容確認は引用条文を開いて行ってください。

#### 例題の自動採点に関する制約

この3段階採点は、次の制約を持つ**登録済み12問専用の開発用回帰テスト**です。

- 質問文を前後の空白を除いて照合し、登録済みの質問文と完全一致した場合だけ採点する
- 例題を少し言い換えた質問、文を付け足した質問、利用者が新しく入力した質問は採点しない
- 新規質問でも通常の検索・回答・引用・根拠図は動作するが、必要条文・回答要点の合否は表示しない
- 必須条文と回答要点は各例題用に人手で定義したもので、任意の質問へ一般化できる採点器ではない
- 回答要点の文字列照合は要点の欠落検出用で、否定、例外、条件、当てはめの正しさまでは判定しない
- 法令改正、投入データ、質問文を変更した場合は、採点用の条文IDと回答要点も人手で見直す
- 12問の成功率はこの開発用例題に対する回帰結果であり、未知の質問への正答率を表さない

新規質問の品質は、引用された条文・資料を開いて回答中の各主張と整合するかを確認してください。
新規質問まで自動採点するには、固定した正解条文ではなく、回答中の主張と引用根拠の整合性を
事後検証する別の評価機構が必要です。

なお、引用の**件数や法令の種類数は検索精度そのものではありません**。複数法令が並んでいても
内容が質問に適合しているとは限らないため、UIでも「複数法令を横断しました」という成功表示は
やめ、引用した資料の一覧と「内容が質問に適合しているかは要確認」の注記に変更しています。

到達しない参照先があっても、質問に法令名を書き足すのは最後の手段です。まず知りたい事柄を
具体語（「申請書に添付する書類」「勧誘時に必要な告知」など）で補ってください。

> **「主な参照先」は毎回同じように引けるとは限りません。** 検索とLLMには揺らぎがあり、
> 同じ質問でも引用が変わります。特に Lv.3 の少人数私募は、定義府令へ到達したのが
> 3回中2回でした（2026-07-25 実測）。**1回の実行結果だけでシステムの能力を判断しないでください。**
> 1回ごとの採点は全項目を満たした場合だけ成功としますが、システムの能力比較には複数回の
> 成功率を使用してください。

全12問を同じ基準で確認する場合:

```bash
TOP_K=5 RUNS=1 CONCURRENCY=1 python3 scripts/check_example_questions.py
```

このスクリプトもAPIへ送るのは質問文と通常の検索設定だけです。終了コードは、全問が3段階の
全項目を満たした場合だけ0になります。揺らぎを見る場合は `RUNS=3` など複数回実行してください。
段階別traceを含むAPIレスポンスを後から調べる場合は、次のように保存先を指定します。

```bash
EXAMPLE_RESULTS_PATH=eval-results/example-questions.jsonl \
TOP_K=5 RUNS=1 CONCURRENCY=1 python3 scripts/check_example_questions.py
```

失敗した例題だけを再確認する場合は、`EXAMPLE_TITLES` にタイトルをカンマ区切りで指定できます。

> Lv.4はガイドラインPDF（`SEED_EXTERNAL_GUIDANCE=true` で投入）が前提です。未投入の場合は
> 条文しか引用されません。

## 4. APIで質問する（UIを使わない場合）

`/answer` に POST します。`choices` を省略すると自由入力（フリーQA）になります。

```bash
curl -s -X POST http://localhost:8000/answer \
  -H 'content-type: application/json' \
  -d '{
        "question": "建物所有目的で土地を借りる場合と、それ以外の場合の期間ルールを、民法と借地借家法を横断して説明してください。",
        "pattern": "pattern_4_deepsearch",
        "topK": 5
      }' | jq '{answer, citations: [.citations[].contentUnitId]}'
```

主なレスポンス項目: `answer`（回答本文）、`citations`（引用条文。`title`/`heading`/
`text`/`sourceObjectUri`）、`route`/`trace`/`graphPaths`（デバッグ用）。

## 5. デジタル庁データセット（lawqa_jp）を手動でテストする

lawqa_jp の選択式140問（金商法80・薬機法39・借地借家法21）を、`eval-runner` で
**1問だけ／数問だけ**実行して、システムの予測回答と正解（gold）を比較できます。

> lawqa_jp は**ゴールデンセット**（正解＋必要な条文を持つ）ですが、それらは採点専用で、
> システムには**問題文と選択肢しか渡しません**（`コンテキスト`＝正解条文の本文は送信しない。
> [run_eval.py](../eval-runner/run_eval.py) の `normalize_lawqa_sample`）。
> gold条文の生成と各指標の詳細は
> [evaluation_design.md](evaluation_design.md) 2.1 を参照。

#### この数値の読み方（重要）

**lawqa_jp の正答率は「開発セット上の性能」であり、未知の質問への汎化性能ではありません。**
モデルを追加学習してはいませんが、以下の形で同じデータセットを開発に使っています。

- 投入する法令の選定に、データセットの参照情報を使っている（[seed.py](../agent-api/app/seed.py) の `_lawqa_egov_law_ids`）
- 特定問題の失敗を調べて実装・設定を変更している（2026-07-25 の `ANTHROPIC_MAX_TOKENS` とタイムアウト調整は、問題番号51の失敗を見て決めた。[test_llm_retry.py](../agent-api/tests/test_llm_retry.py) 参照）
- 同じ20問の抜粋で繰り返し前後比較している

**設問自体にヒントが含まれる点**にも注意が必要です。140問を数えると、問題文または選択肢に
条番号（第N条）を含むものが95問（68%）、法令名を含むものが89問（64%）あります。特に
「根拠条文」型32問は選択肢が100%条文名そのもので、[agent.py](../agent-api/app/agent.py) の
`article_direct_lookup` がその条番号を直接引きに行きます。純粋な検索能力を測るなら、
条番号がどこにも現れない「関連法令」型45問だけを抜き出すのが適切です。

### 5.1 事前準備

法令・ガイドラインが seed 済みであること（RUNBOOK.md の seed 手順）。以下は
`EVAL_SKIP_SEED=true` で**再seedせず**に評価する前提です。

### 5.2 特定の1問だけ実行する

問題はデータセットの**並び順**で指定します（`EVAL_OFFSET` = 先頭から数えた0始まりの位置、
`EVAL_LIMIT=1` = 1問だけ）。例: 5番目の問題を実行:

```bash
LAWQA_EVAL_URL=https://raw.githubusercontent.com/digital-go-jp/lawqa_jp/main/data/selection.json \
EVAL_OFFSET=4 \
EVAL_LIMIT=1 \
EVAL_PATTERN=pattern_4_deepsearch \
EVAL_SKIP_SEED=true \
docker compose --profile eval run --rm eval-runner
```

結果は `eval-results/eval-<日時>.jsonl` に1行で書き出されます。

### 5.3 数問まとめて実行する（例: 先頭10問）

```bash
LAWQA_EVAL_URL=https://raw.githubusercontent.com/digital-go-jp/lawqa_jp/main/data/selection.json \
EVAL_LIMIT=10 \
EVAL_PATTERN=pattern_4_deepsearch \
EVAL_SKIP_SEED=true \
docker compose --profile eval run --rm eval-runner
```

### 5.4 結果の読み方

出力 JSONL の各行から、予測回答と正解、正誤を取り出します:

```bash
latest=$(ls -t eval-results/*.jsonl | head -1)
jq -c '{問題: .questionId, 予測: .predictedAnswer, 正解: .goldAnswer, 正誤: .scores.answerAccuracy, LLM使用: .llmUsed}' "$latest"
```

- `scores.answerAccuracy` が `1` なら正解、`0` なら不正解。
- `citations` と `retrievedContentUnitIds` は最終引用。候補プール全体はAPI traceの
  `candidatePoolContentUnitIds` で確認する。
- `scores.citationArticleHit` は期待条文のどれか1条への到達（従来互換）。
- `scores.citationArticleCompleteHit` は期待条文を全部取得できたか、
  `scores.citationArticleRecall` は期待条文のうち取得できた割合。集計の
  `citationArticleRecall` は問題単位のマクロ平均、`citationArticleMicroRecall` は
  全期待条文を分母にした再現率。各問題の件数は `articleCoverage` で確認できる。
- 候補プール、融合、再ランクにも同名の `*ArticleCompleteHit` / `*ArticleRecall` がある。
- `datasetIssue` は法令時点・誤gold・複数正解の確認対象。公式正答率を変更せず、
  これらを除く診断値を `diagnosticAnswerAccuracyRate` として別に集計する。
- `llmUsed` が `false` の場合はタイムアウト等でLLM判定が行われていない（結果は参考外）。

特定の問題を名前で拾いたいときは、範囲実行した結果を `questionId` で絞り込みます:

```bash
jq -c 'select(.questionId | test("借地借家")) | {questionId, predictedAnswer, goldAnswer}' "$latest"
```

## 6. うまく回答されないとき

- **範囲外の質問**: 第2章「回答できる範囲」を確認。民法は賃貸借のみです。
- **引用が見つからない / 1つの法令しか引かれない**: 法令名を足す前に、**知りたい事柄を
  具体語で足す**のが有効です（「申請書に添付する書類」「勧誘時に必要な告知」など）。
  実際、施行規則や定義府令へ届かなかった質問例は、この言い換えだけで到達しました。
  それでも足りなければ「根拠条文も示して」を付ける、Top Kを増やす、の順で試します。
- **時間がかかる/タイムアウト**: `pattern_4_deepsearch` は探索が深く時間がかかります。
  詳細設定で `pattern_2_rule_based_agentic_rag` に下げると速くなります。
- **サービスが応答しない**: `docker compose ps` で各コンテナの状態、
  `docker compose logs -f agent-api` でログを確認。
